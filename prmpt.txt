The audience is researchers and reviewers in autonomous driving / RL. Goal: make the core idea understandable in 60 seconds and let visitors verify the claims interactively.

- Keep all paper numbers in one file src/data/results.ts, typed, so they are easy to correct. Keep all simulation parameters in src/data/params.ts.

## Demo specifications

### Demo 1 - Horizon mismatch
Timeline visualization with three selectable modes: Direct N_ss=1, Direct N_ss=20, REVAMP (Lookahead N_ss=20, dt'=0.1). Show the 2 s planned path as a bar, the retained portion highlighted (0.1 s for N_ss=1 and REVAMP; the full 2 s for Direct N_ss=20), and a replanning-frequency indicator (10 Hz / 0.5 Hz / 10 Hz). A small animated car replans at the corresponding frequency. One-sentence takeaway per mode taken from the paper.

### Demo 2 - Reversible lookahead step-through (the hero demo)
Top-down 2D mini-simulation (a road with a curve or intersection, 2-4 vehicles, one stationary obstacle). Vehicles use a kinematic bicycle model and follow their Bezier paths with the Appendix A controller (pure pursuit + heading/cross-track correction, PID speed). Since no trained policy runs in the browser, use a scripted "policy" that emits plausible normalized 11-dim actions (a few presets, plus an "add noise" toggle).
- Stepper following Algorithm 1: 1 observe, 2 sample action, 3 decode trajectories, 4 deep copy state, 5 lookahead rollout for k=1..N_ss (draw ghost vehicles advancing along all agents' paths JOINTLY, so interactions are visible), 6 aggregate lookahead reward, 7 discard copy (ghosts fade out), 8 advance real state by one 0.1 s step, 9 combine r = r_real + r_look. Highlight the current step, show short explanatory text, allow auto-play with speed control.
- Controls: N_ss (1-20), dt' (0.05-0.3 s), toggle "stop rollout on collision/off-road" (events stop the temporary rollout but never terminate the retained episode; state this in the UI).
- Side panel: live reward breakdown for the current step (r_real terms, r_look terms), with the c_k weights (Eq. 20) drawn as a small bar chart.
- Add a comparison switch: "Direct N_ss=20 (retain all substeps)" vs "REVAMP" to show the difference in what the simulator state retains.

### Demo 3 - Bezier action playground
- 11 sliders for the normalized action a = [a0^hx, a1(5 dims), a2(5 dims)] in [-1,1], grouped by control point, plus draggable handles on the canvas that update the sliders (bidirectional).
- Ego speed slider. Implement decoding exactly per Appendix A: s = 2 + v/4; BE0=(0,0); BH0 = (1 + (a0hx+1)/2 * s, 0); BEx_i = (a_ex_i + 1.1) * s_i, BEy_i = a_ey_i * s_i; v*_i = 10(a_v_i + 1); BHx_i = BEx_i + (a_hx_i+1)/4 * s; BHy_i = BEy_i + a_hy_i/2 * s; two cubic segments with C2 = 2*BE_{i+1} - BH_{i+1}; sample 50 points; linearly interpolate target speed. Note: verify the paper's notation for s_i against Appendix A and flag any ambiguity in a code comment.
- Show: the path, P0/P1/P2 markers, handles, target-speed profile chart, and a vehicle tracking the path with the controller (Eq. 41-45 params). Preset buttons: straight, gentle left, sharp right, stop.

### Demo 4 - Side-by-side qualitative comparison
Three synchronized panels (Direct N_ss=1, Direct N_ss=20, REVAMP) x three scenario tabs (curved road, intersection, overtaking). Load pre-recorded rollouts (JSON schema below) and render on canvas, or fall back to <video> files if provided. Overlay the full predicted 2 s path at each policy step (toggle). Shared scrubber, play/pause, frame-step. Under each scenario, show the paper's one-paragraph interpretation (e.g. N_ss=1's unexecuted path crosses the obstacle; N_ss=20 leaves excessive clearance; REVAMP is decisive with adequate clearance). Ship placeholder synthetic rollouts so the UI works before real data arrives.

Rollout JSON schema (document in README, validate at load):
{ "scenario": string, "method": "direct1"|"direct20"|"revamp", "dt": 0.1,
  "map": { "roads": [[[x,y],...]], "edges": [[[x,y],...]], "goal": [x,y] },
  "obstacles": [{ "x":..,"y":..,"heading":..,"length":..,"width":.. }],
  "frames": [ { "t": number, "agents": [ { "id":int, "x":..,"y":..,"heading":..,"speed":..,"length":..,"width":..,
        "plan": [[x,y],...50 pts] (optional), "lookahead": [[[x,y],...],...] (optional) } ] } ] }

### Demo 5 - Lookahead reward explorer
Given a chosen scenario from Demo 2, plot per-step contributions q_k = align + eff + prog + col + off (Eq. 19), weighted by c_k = (0.5 + 1.5k/N_ss)/N_ss, as a stacked bar over k=1..N_ss, plus the one-time control-point term and the goal term R_goal*(N_ss - k_g). Use Appendix C parameters (Tables VI, VII) with an editable coefficient panel and a "reset to paper values" button. Include short tooltips for each term, following Section IV-C.

### Demo 6 - Results explorer
Tabs: Direct vs Lookahead (Table II), WOSAC (Table III), Resolution (Table IV), Robustness (Table V). Bar charts with error bars (mean +/- SD), metric selector, sort/highlight best, and a "why this matters" caption per tab. In the WOSAC tab include SMART-R1 as a clearly labeled external reference that is NOT a controlled baseline. In the Table II view include the caveat that Direct variability is across checkpoints while Lookahead variability is across seeds. Be careful not to overclaim: Direct N_ss=1 has the best collision/off-road/success numbers, and the paper's argument is about complete-trajectory quality; show that honestly.

### Demo 7 - Resolution trade-off
Scatter/line chart: SPS (x) vs success (y) with DNF as marker size or a second panel, for (7,0.3), (10,0.2), (20,0.1). Hover cards with all Table IV metrics. Caption: (10, 0.2) is the favorable compromise; (7, 0.3) degrades badly (70.18% success, 20.50% DNF with high variance).

### Demo 8 - Observation corruption
Left: a top-down ego-centric observation view (ego, partners, road segments) with a slider for xi in [0, 1.5]. Implement Appendix B: p_miss = min(1, xi*0.10), p_phantom = min(1, xi*0.05) (phantom placed with d = sqrt(dmin^2 + U(dmax^2 - dmin^2)), dmin=5, dmax=50, random bearing/heading, speed in [0,15], 1.8x4.5 m), Gaussian noise scaled by xi with the nominal sigmas from Eq. 53-54. Draw true vs corrupted positions (missed = dashed outline, phantom = red ghost). "Resample" button. Right: the 3x3 train-xi x eval-xi heatmaps from Table V (success, collision, off-road, alignment) with a metric switch.

### Demo 9 - Self-play showcase
A looping grid of 4-6 short clips (video or canvas replays) of many agents driving together on CARLA-derived maps, with a caption explaining shared-policy self-play, agent-level goals and respawning. Placeholder assets until real ones are supplied.

### Demo 10 (optional, behind a feature flag) - Encoder attention viewer
Replay viewer for an ego agent's observation where partner/road tokens that win the max-pool in the encoder are drawn with a glow. Data comes from an optional JSON field per agent: "selected_partner_ids", "selected_road_ids". Disabled by default; clearly labeled "Additional analysis, not in the paper".
